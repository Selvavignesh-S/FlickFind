01What we're building

A movie recommender you talk to, which understands your mood before it searches.

You tell FlickFind how you feel or what you want. If it needs to know more, it asks one short question with quick-reply buttons (for example: laugh it off, have a good cry, stay in it, distract me). Then it shows up to five films that really fit, each with a sentence on why. If fewer fit well, it shows fewer and offers Find more.

It learns from what you watch, rate and block, not from your watchlist. Over time it drifts from well-known picks toward niche ones if that is where your taste goes. Blocked films never come back unless you unblock them.

04How the pieces fit

Building the catalog and serving the app run at different times. The only link between them is one file in a bucket.

1 · Build

Scripts turn IMDb and TMDB data into a curated catalog. Your GPU writes a mood profile for each film, and fastembed turns it into a vector.

2 · Store

A private B2 bucket keeps each catalog version. It is a delivery point; nothing searches it directly.

3 · Serve

FastAPI holds the catalog in RAM, keeps user data in SQLite, and calls the AI only to understand you and to judge candidates.

4 · Use

One Expo app runs in the browser and on your phone. It only ever talks to the backend.

Vote floors are starting points. Step 3 prints how many films survive at each floor for each group, and you pick the final numbers from that report.

The build pipeline

  1. Gather. Download IMDb's title.basics and title.ratings. Keep movie and tvMovie, 60+ minutes, not adult, with at least 20 votes (a loose first cut).
  2. Fetch. Find each film on TMDB by its IMDb id, then fetch its details in one call with append_to_response=credits,keywords,release_dates,watch/providers,reviews. Every raw response is saved, so a rebuild doesn't call the API again. Shortcut: your old parquet already pairs TMDB ids with IMDb ids, which skips most lookups.
  3. Curate. Apply the language scope, the vote floors, the video flag, the released status and the synopsis-length rule. Print the count report and pick the floors.
  4. Mood profile. The local AI reads the synopsis, tagline, genres, keywords and up to 3 review excerpts, about 20 films per call, and returns a structured profile (below).
  5. Embed. Build each film's mood document and turn it into a vector of 256 numbers.
  6. Package. Write catalog-vYYYYMMDD.parquet and manifest.json.
  7. Upload to the private B2 bucket.

Mood profile: the heart of the catalog

Every film gets the same structured description, using a fixed vocabulary so profiles can be compared and filtered. The vocabulary has about 60 tags, finalised in Phase 2. Effects:

liftcatharsiscomforttensionescapeprovokenumb

Sample tags:

melancholicbittersweetupliftingcozyeeriedreamliketenderbleakwhimsicalnostalgiclonelyawe-inspiringslow-burnmeditativefranticgriefcoming of agefamilysurvivalidentity 
{
  "mood_tags": ["melancholic", "tender", "bittersweet"],
  "effect": "catharsis",
  "pace": "slow",
  "intensity": 2,
  "watch_when": "you want to sit with sadness rather than escape it",

Before the full run we hold a 50-film bake-off: the local model and Gemini write profiles for the same films, and you compare them side by side. The full run then goes on your GPU, with checkpoints so it can stop and resume.

Mood document and vector

search_document: Tokyo Story (1953). Drama. Japanese.
Mood: melancholic, tender, quiet. Effect: catharsis. Pace: slow.
Keywords: aging parents, generation gap, family.
Watch when: you want to sit with sadness rather than escape it.
Synopsis: An elderly couple travels to Tokyo to visit their grown children ...
  • Embedded with nomic-embed-text-v1.5 (ONNX), prefix search_document:, cut to 256 dimensions and stored at half precision. Nomic loses only about 1.2 benchmark points at 256 versus 768.
  • The model, prefix and size are written into manifest.json. The backend refuses to start if its embedder doesn't match, so search can never silently break.

06Workflow: one chat turn

Two AI calls with a fast, exact search between them. The first call can stop early to ask a question.

Step 1 · Understand (AI call 1)

A cheap model reads the chat so far plus a short summary of your preferences, and returns:

{
  "action": "ask",                  // ask | recommend | more | chat
  "question": "Feeling low. What would help tonight?",
  "chips": ["Laugh it off", "Have a good cry", "Stay in it", "Distract me"],
  "mood": "sad, tired",
  "effect": null,                   // lift | catharsis | comfort | tension | escape | provoke | numb
  "synopses": [],                   // 1–3 imagined film synopses that would fit
  "filters": {"languages": [], "year_min": null, "year_max": null,
              "runtime_max": null, "genres": [], "not_genres": []},
  "needs_fresh": false              // true for "new", "this year", "in theatres"
}
  • When it asks: the effect is unknown and you described a feeling ("I'm sad"), or the request is too vague ("something good"). It asks at most two questions in a row, then makes its best guess and says what it assumed.
  • Quick replies map to effects: Laugh it off → lift · Have a good cry → catharsis · Stay in it → numb · Distract me → escape · Comfort me → comfort.
  • The understood intent is saved with the chat, so Find more can reuse it without another AI call.

Step 2 · Search

  • Each imagined synopsis is embedded the same way as catalog films, because it imitates one. Your raw message is embedded too, as a query. A film's mood score is its best match against any of them. We confirm this setup with the golden prompts.
  • Filters run first, as a mask: not blocked, not watched, not shown in this chat, not in an avoided language, no avoided actor in the top-5 cast, at least the vote floor for your niche score, plus the intent's own filters (years, runtime, genres).
  • The top 200 films by mood score go on to scoring.

Step 3 · Score and spread

score = mood_match
      + 0.35 × liked_profile_match   − 0.35 × disliked_profile_match
      + 0.10 × favourite_genre       − 0.15 × avoided_genre
      + popularity_weight(n) × popularity
      − 0.20 × shown_before          // fades to 0 over 30 days

Weights are starting values, tuned with the golden prompts. Then a spreading step (MMR) picks 25 films that score well but aren't near-copies of each other. This is what stops "five slow Japanese family dramas" when one would do.

Step 4 · Judge (AI call 2)

The AI sees the 25 candidates, one compact line each, and returns only ids, scores and reasons:

[{"id": 18148, "fit": 9, "why": "A quiet, aching film about parents and grown children drifting apart."},
 {"id": 12477, "fit": 8, "why": "..."},
 {"id": 603,   "fit": 3}]
  • Scoring guide given to the AI: 10 delivers exactly the feeling you asked for · 7 clearly fits · 4 only the genre overlaps.
  • A film is shown if it scores 7 or more and is within 2 points of the best. At most 5 are shown.
  • Any id that wasn't among the 25 is thrown away. Card details always come from the catalog, never from the AI.
  • Shown films are saved as impressions so they don't repeat.

Find more

AI budget: 2 calls per turn, 1 when it only asks a question, and 1 for Find more. When Gemini's free limit runs out, the same prompts go to Groq.

Two taste profiles, not one

Your liked profile is the average vector of films you rated well, plus "About me". Your disliked profile is the average of films you rated badly or blocked for theme. A film scores higher when it is close to the first and far from the second. Neither is ever mixed into the search vector itself, so a horror lover who asks to be cheered up still gets cheered up.

Drifting from Normal to Niche

obscurity(film)  = the film's rank by IMDb votes within the catalog, 0 = hugely popular, 1 = rarely seen
on a 4–5★ rating:  n ← n + 0.10 × (obscurity − n)         // change capped at ±0.05 per day
vote_floor(n)    = e^( (1−n)·ln 1000 + n·ln dataset_floor )  // 1000 → ≈140 → floor
popularity_weight(n) = clamp(0.15 × (1 − n/0.6), −0.05, 0.15)

The header shows the label: Normal (below 0.33), Explorer (0.33–0.66) or Niche (above 0.66). A one-chat override ("go mainstream tonight") changes only that chat, never n.

08Workflow: staying fresh

New releases arrive through a small daily job, not through searching the web on every request.

JobWhenWhat it does
Daily updateEvery day at 04:00 (systemd timer on your PC)Pulls TMDB's now-playing, upcoming and recently changed films. Applies the same curation rules, writes mood profiles with the local AI, embeds them, and uploads a small delta file. Also refreshes IMDb ratings and vote counts.
Monthly rebuild1st of every monthRuns the full pipeline from cached raw data, re-fetching what changed. Folds in the daily updates and users' mood notes. Also satisfies TMDB's rule against keeping its data more than 6 months.

09Workflow: web fallback

Your agentic idea, in the form free services allow: a short, fixed pipeline that runs only when the catalog can't help.

When it runs

You ask for something recent ("new this month"), or Find more has run out of catalog films, or you ask it to search the web.

What it does

1 web search through Gemini's built-in Google Search, with Tavily as backup · titles taken from the result snippets only · each title looked up on TMDB, unknowns dropped · mood profile + vector · AI call 2 judges them like any other film.

Limits

At most 2 searches and 20 seconds per turn. Every film it finds is saved to the catalog, so the same question is answered locally next time.

Why not read Reddit and Letterboxd directly

Reddit's API now needs manual approval, and Letterboxd's API is closed. Quora, MUBI and Tubi have none. Search snippets still surface what those communities recommend, without scraping.

16Testing and quality

Code tests catch bugs. Golden prompts catch bad recommendations.

Unit tests

Filter mask, scoring, MMR, the fit-bar rule, the id check, niche updates and caps, each block effect, Find more steps, token checks.

Golden mood prompts (30)

Vague prompts, sad prompts with each quick reply, language-specific prompts, niche prompts, "something new". Tracked: off-mood rate, repeat rate, and how often vague prompts get a question.

Dataset checks

The build report every run: counts per step, drops per rule, language and decade spread, a 100-row spot check, and the manifest compared with the embedder.

Real-world signal

Niche users' "how well did it match your mood?" answers, compared with the AI's fit scores, tell us whether the bar of 7 is right.
